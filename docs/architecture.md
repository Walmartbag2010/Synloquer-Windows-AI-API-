# 架构概览

## 项目定位

Silver Telegram 是一个纯终端的 LLM 对话助手，基于 Python 实现，无 Web 界面，无 GUI 框架，仅依赖 `requests` 库。核心设计目标是**轻量化、可配置、多模型适配**。

## 核心数据流

### 对话流程

```
用户输入
  │
  ▼
main() 输入循环
  │
  ▼
chat_stream(user_input)
  │
  ├─▶ messages.append({"role": "user", "content": user_input})
  │
  ├─▶ 工具调用循环（最多 8 轮）
  │     │
  │     ├─▶ _get_provider_endpoint()  获取端点
  │     ├─▶ _get_provider_headers()   获取请求头
  │     ├─▶ _build_chat_request()     构建请求体
  │     ├─▶ requests.post(stream=True) 发送请求
  │     │
  │     ├─▶ 流式解析循环
  │     │     ├─▶ _parse_stream_line() 解析每一行
  │     │     ├─▶ 累积文本内容 assistant_content
  │     │     └─▶ 累积工具调用 tool_calls
  │     │
  │     └─▶ 如果有 tool_calls
  │           ├─▶ 保存 assistant 消息（含 tool_calls）
  │           ├─▶ 执行每个工具（TOOL_FUNCTIONS 分发）
  │           ├─▶ 保存 tool 结果消息
  │           └─▶ 进入下一轮循环
  │
  └─▶ 返回最终回复
```

### 退出流程

```
用户输入 exit / Ctrl+C
  │
  ▼
检查是否有对话内容
  │
  ├─▶ summarize_conversation()  生成对话总结
  │     └─▶ 用 MODEL_SUMMARY 模型非流式调用
  │
  ├─▶ save_summary()            保存到 summaries/
  ├─▶ save_chat_log()           保存到 chat_logs/
  └─▶ update_memory()           更新长期记忆
        ├─▶ 用 flash 模型生成新记忆
        ├─▶ 安全校验（长度突变检测）
        ├─▶ 备份旧记忆（.bak）
        └─▶ 写入 memory.md
```

## 关键设计决策

### 1. 无框架依赖

仅使用 Python 标准库 + `requests`，不引入 Flask、FastAPI、LangChain 等框架。原因：
- 终端交互不需要 Web 服务器
- 工具调用逻辑简单，不需要 Agent 框架
- 减少依赖体积，启动更快

### 2. Provider 适配层而非多客户端

不使用 `openai`、`anthropic` 等官方 SDK，而是通过适配层统一处理。原因：
- 官方 SDK 体积大，且各 SDK API 不一致
- 适配层只需处理 headers、endpoint、request body、response parse 四个维度
- 新增 provider 只需添加配置和适配逻辑，不需要新依赖

### 3. 工具调用用 OpenAI 格式

工具定义和调用遵循 OpenAI Function Calling 格式，因为：
- DeepSeek 原生支持
- 大多数兼容 OpenAI 格式的服务商都支持
- Anthropic 暂不发送 tools（后续可扩展转换）

### 4. 记忆更新用追加保留式

长期记忆更新时，prompt 明确要求"必须保留已有记忆中的所有信息点"，并添加长度安全校验和备份机制。原因：
- 防止模型总结时丢失重要信息
- 长度突变（新记忆明显短于旧记忆）时触发警告并追加而非覆盖
- 备份机制允许手动恢复

### 5. 图片查看用旧版 Windows 照片查看器

通过 `rundll32 PhotoViewer.dll ImageView_Fullscreen` 调用旧版照片查看器，而非 `os.startfile`。原因：
- 不依赖文件关联（避免弹出"打开方式"对话框）
- 轻量级，启动快
- 可通过 Windows API 调整窗口大小
- 进程完全分离，不阻塞终端
